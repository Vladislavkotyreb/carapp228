# Решения

Каждое продуктовое и архитектурное решение с причиной. Решение, которого здесь
нет, будет переспорено заново — это и есть единственный смысл файла.

Отменённое не удаляется, а получает строку «отменено» с датой и причиной:
иначе через месяц никто не вспомнит, что вариант уже пробовали.

Что сюда **не** идёт: состояние компонента — [`STATE.md`](STATE.md), механизм
поломки — [`TRAPS.md`](TRAPS.md), что сделано — [`JOURNAL.md`](JOURNAL.md).

## Продукт и данные

| Решение | Почему |
|---|---|
| Хранение локальное, на SwiftData | 152-ФЗ: приложение для РФ, Supabase хостится вне России. Пока данные не покидают телефон, обязанностей оператора ПДн нет |
| Supabase удалён целиком | Он не работал: экраны авторизации были недостижимы из `RootView`, схема на сервере шаблонная (`profiles`, `items`) |
| Наличие машины выводится из базы | Раньше был флаг `hasAddedCar` в `UserDefaults` — он разъезжался с данными |
| Ключ поставщика поиска по госномеру — только на сервере | Ключ в `.ipa` достаётся за минуты, за него спишут баланс платного API |
| Системное стекло важнее совпадения с растром Figma | Макет сам ссылается на системный компонент `Liquid Glass`, растр — лишь его приближение |
| Блик по наклону — своя реализация на CoreMotion | Публичного API нет: у `Glass` только `regular/clear/identity/tint/interactive`, у `UIGlassEffect` — `interactive/tintColor` |
| Свайп карусели только в верхней зоне (620pt) | Снимает конфликты жестов с вертикальным скроллом и лентой ТО, которые ломали экран несколько раз |
| Белые карточки на странице «добавить новую» гаснут целиком, с подложкой | В ноде `45949:3265` их там нет вовсе. Для тёмной карточки правило прежнее — подложка остаётся, меняются надписи |
| Белая подложка под «Историей обслуживания» снята | Отступление от ноды `45893:3541`, где вся история лежит в одной белой карточке 370×350. Просьба пользователя; вместе с подложкой убран и её внутренний отступ 16, иначе блок был бы на 32pt уже остальной страницы |
| Развилки раскладок нет: страница одна, различия смешиваются числами | Решение «менять тело на середине свайпа» на устройстве читалось как поломка. Отличий всего четыре и все они числа — зазоры, высота карточки и наличие истории, — поэтому они смешиваются, а не переключаются. В покое каждая машина по своей ноде, в движении ничего не прыгает |
| Кнопки подняты над home indicator | В Figma home indicator не нарисован, макет доходит до края экрана, и кнопки заезжали на него даже на макетном устройстве |

## Дизайн и реализация

| Решение | Почему |
|---|---|
| Таббар не повторяем, а берём системный | Компонент в макете — `Tab Bar - iPhone` из дизайн-кита Apple, с вариантом `Minimized`: дизайн с самого начала описывал системный элемент, а мы его перерисовывали. `TabView` + `Tab` + `tabBarMinimizeBehavior(.onScrollDown)`. Своя реализация осталась веткой для iOS 17–25 |
| Схему задаём бару, а не экрану | В макете бар светлый (`BG mode="Light"`), а экран тёмный ради светлого статус-бара. `environment(\.colorScheme, .light)` вешается на `TabView`, каждая вкладка возвращает себе тёмную |
| Шторки, тост и рамка живут снаружи `TabView` | Внутри вкладки системный бар рисуется поверх её содержимого, и шторка ушла бы под него |
| Таббар скрыт под модалкой записи — по HIG, а не по макету | На рендере `46105:3970` бар во время записи виден, и геометрически он с панелью не спорит. Но модальное окно на то и модальное, что забирает управление себе. Сделано по прямой просьбе |
| Заголовок шторки находок — по центру, как в системе | В макете он слева и перекрыт крестиком с галочкой: экземпляр `Toolbar - Top - iPhone` не растянут под длинный заголовок (trailing-слот на x=174 вместо правого края). Это дефект макета, а не решение дизайнера |
| Развилки раскладок нет: страница одна, различия смешиваются числами | Подмена тела экрана на середине свайпа читалась на устройстве как поломка. Отличий всего четыре и все они числа |
| Переменные Layout в Figma к слоям **не привязаны** | Привязка меняет исходник дизайна и откатывается только историей версий Figma |
| Ключ Yandex MapKit лежит в приложении | У мобильных SDK карт другая модель: ключ привязан к бандлу и секретом не является. Решению «ключ поставщика только на сервере» это не противоречит |
| Рамка прослушивания снята 18.08.2026 | По просьбе. Механизм рабочий, описан в [`JOURNAL.md`](JOURNAL.md), вернуть можно ревертом коммита |
| `SoundOrb.style` = `.blob` оставлен включённым | По просьбе, при том что `.blob` заметно расходится с макетом: там волна внутри тёмного пузыря, а у блоба деформируется сам контур. Решение за дизайном, откат — замена одной константы |

## Разбор звука

| Решение | Почему |
|---|---|
| Пишем WAV, а не m4a | Сервер читает файл через `soundfile`, тот берёт PCM без ffmpeg. С m4a на сервер пришлось бы ставить ffmpeg ради ничего |
| Привратник «мотор ли это» вынесен в свой сервер `tools/diagnosis_server.py` | У модели нет класса «здесь вообще нет машины» ни у одной головы — внутри ответа этого не поймать. CLAP спрашивается напрямую; приём взят из самого пайплайна, где так отсеивается музыка. Замер: синтетический мотор 0.86 против 0.10…0.38 у пяти записей без мотора |
| Версии показываем только при `verdict == "fault"` | Голова причин отвечать «ничего» не умеет, голова `kind` умеет и вдобавок откалибрована — она и служит воротами |
| Жёсткий запрет по `segments == 0` снят | Порог громкости в каскаде относительный, поэтому ровно урчащий мотор кусков не даёт так же, как тишина: запрет отрезал бы настоящие записи. Осталось оговоркой |
| Причины ниже 5 % отбрасываются, первая строка остаётся всегда | «Уверенность 0 %» читается как найденная неисправность. Пустая шторка хуже честной цифры |
| Две вероятности не смешиваются в одно слово | `fault_probability` откалибрована (температура 3.08, ошибка ≈ 0.04) и читается как вероятность. `causes[].p` — распределение по 21 семейству с температурой 1.0, не калибровано вовсе. Первая карточка отдаёт калиброванное число, у версий стоит «модель ставит сюда» |
| Шторка находок открывается только после ответа | Показать её сразу и потом подменить содержимое значит соврать про то, что уже «нашли» |
