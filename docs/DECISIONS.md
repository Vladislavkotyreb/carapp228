# Решения

Каждое продуктовое и архитектурное решение с причиной. Решение, которого здесь
нет, будет переспорено заново — это и есть единственный смысл файла.

Отменённое не удаляется, а получает строку «отменено» с датой и причиной:
иначе через месяц никто не вспомнит, что вариант уже пробовали.

Что сюда **не** идёт: состояние компонента — [`STATE.md`](STATE.md), механизм
поломки — [`TRAPS.md`](TRAPS.md), что сделано — [`JOURNAL.md`](JOURNAL.md).

От разницы прибавка идёт в пробег, убавка сверенный пробег не трогает (`TripMath.adjust`). Линия маршрута не меняется — человек правит число |

Цена: такси от знакомого места стоянки засчитается — поэтому поездку можно удалить. Мест помним шесть, а не одно: пропустили поездку — следующая от дома или работы подхватится, иначе автоопределение молча умирало бы до ручной поездки. Первая поездка после включения считается откуда угодно: мест ещё нет (09.10.2026, `TripAuto`) |
| Автопробег привязывается к Bluetooth машины; привязанная машина получает поездки, только пока он подключён (12.10.2026) | Просьба пользователя после разговора о телеметрии: у каршеринга блок в машине, у такси — заказ, нам доступен только телефон. Геопозиция и датчики такси от своей машины не отличают, а выход звука отличает и виден закрытому приложению. Привязка — по выходу, а не по устройству Bluetooth: обычный Bluetooth магнитолы не маячок, ни найти его, ни проснуться от него приложение не может. Будят по-прежнему зоны и «значимое перемещение»; привязка решает, чья поездка и поездка ли. Без своей машины перемещение не слушаем вовсе, выход из зоны ждёт минуту — Bluetooth бывает медленнее машины. Привязывается машина из строки «Машина»: одна строка на экран, а не список; имя выхода — в вопросе до привязки, чтобы не привязать наушники. Непривязанные машины живут по-старому. Цена: магнитола только со звонками (HFP) без вызова в выходах не видна, и такой машине привязка не поможет (`TripLink`) |

Анонимный аккаунт не стоит ничего, а iCloud Keychain переносит его на новый айфон того же Apple ID. Конфликты решает сервер (новее побеждает, удаление окончательно); что слать, телефон решает отпечатками полей, а не слежкой за правками по экранам (`SyncPlan`) |

## Состояние экранов

| Решение | Почему |
|---|---|
| Состояние раздела «Ошибки» — одно значение `IssuesActivity`, а не два булевых | «Записываю» и «разбираю» одновременно — состояние, которого не бывает. Пока это два флага, оно выразимо, и тест на него ничего не даст: надо, чтобы багу было негде жить |
| Старые читатели (`isRecording`, `isAnalyzing`) оставлены вычисляемыми | Правка так свелась к четырём присваиваниям вместо переписывания вёрстки. Собрать приложение на машине, где велась работа, нечем — чем меньше диф, тем меньше риск |
| Деятельность и наличие истории — два разных измерения, в один тип не сводятся | История остаётся, пока идёт запись, и меняется без участия деятельности. Фаза экрана выводится из обоих в `IssuesPhase.of` |
| Модалки «Машины» — один слот `CarSheet`, а не пять булевых | Пять флагов дают 32 сочетания, законных шесть. Две открытые шторки — не абстрактная опасность: в этом файле уже ловили, как общий пикер фото открывал чужую модалку |
| Слот отдаётся presentation-API вычисляемым `Binding<Bool>` | Иначе пришлось бы переписывать вызовы `.bottomSheet` / `.sheet` / `.photosPicker` / `.confirmationDialog` и дочерний `CarMainChrome`. Так правка свелась к замене аргумента |
| Закрытие сбрасывает слот только для своей шторки | SwiftUI досылает `false` уходящей уже после того, как открылась следующая; безусловный сброс закрывал бы её |
| `editingRecord` оставлен отдельным полем | Это данные о том, что правят, а не то, какое окно открыто. То же разделение измерений, что «деятельность против истории» в «Ошибках» |
| Типы фаз заведены раньше перевода вью на них | На типах держится каталог состояний, а каталог, собранный руками, назавтра разойдётся с приложением молча |

## Разбор звука

| Решение | Почему |
|---|---|
| Разбор звука — локально на устройстве, Core ML | Прямая просьба пользователя. Телефону нужна только аудио-башня CLAP (58 МБ fp16), а не «2 ГБ с torch»: головы линейные, текстовые эмбеддинги промптов предвычислены. Запись не покидает телефон (152-ФЗ не встаёт), работает офлайн в гараже, хостинг не нужен. Сервер — отладочный запасной путь |
| Мел-фронтенд — отдельная fp32-модель | У power-спектра динамический диапазон ~200 дБ: fp16 переполняется на громком (cos падал до 0.982) и глохнет в денормалах на тихом. Трансформеру fp16 хватает: cos ≥ 0.99998 |
| Паддинги повторяют сервер буквально: привратник — нули, головы — repeatpad | У сервера они РАЗНЫЕ (`Clap.score` с padding=True против `Clap.embed` с дефолтом), и все пороги сняты с этого поведения. «Исправить» на единый паддинг значило бы уйти от замеров |
| Пишем WAV, а не m4a | Сервер читает файл через `soundfile`, тот берёт PCM без ffmpeg. С m4a на сервер пришлось бы ставить ffmpeg ради ничего |
| Привратник «мотор ли это» вынесен в свой сервер `tools/diagnosis_server.py` | У модели нет класса «здесь вообще нет машины» ни у одной головы — внутри ответа этого не поймать. CLAP спрашивается напрямую; приём взят из самого пайплайна, где так отсеивается музыка. Замер: синтетический мотор 0.86 против 0.10…0.38 у пяти записей без мотора |
| Версии показываем только при `verdict == "fault"` | Голова причин отвечать «ничего» не умеет, голова `kind` умеет и вдобавок откалибрована — она и служит воротами |
| Жёсткий запрет по `segments == 0` снят | Порог громкости в каскаде относительный, поэтому ровно урчащий мотор кусков не даёт так же, как тишина: запрет отрезал бы настоящие записи. Осталось оговоркой |
| Причины ниже 5 % отбрасываются, первая строка остаётся всегда | «Уверенность 0 %» читается как найденная неисправность. Пустая шторка хуже честной цифры |
| Две вероятности не смешиваются в одно слово | `fault_probability` откалибрована (температура 3.08, ошибка ≈ 0.04) и читается как вероятность. `causes[].p` — распределение по 21 семейству с температурой 1.0, не калибровано вовсе. Первая карточка отдаёт калиброванное число, у версий стоит «модель ставит сюда» |
| Шторка находок открывается только после ответа | Показать её сразу и потом подменить содержимое значит соврать про то, что уже «нашли» |
