# Разбор звука двигателя: подключённый cardiag

Раздел «Ошибки» больше не выдумывает находки. Запись с микрофона уходит в
[adam-s/car-diagnosis](https://github.com/adam-s/car-diagnosis) (`cardiag`,
MIT) и возвращается разбором.

## Что это за проект и чего от него ждать

Пайплайн на Python: запись чистится каскадом (речь, музыка и шум отсекаются,
остаётся механический звук), кодируется замороженной моделью CLAP в 512-мерный
вектор, дальше линейные головы дают вердикт, зону и ранжированные детали.

Автор честно называет это triage aid, и цифры из его модельной карты стоит
держать в голове, прежде чем обещать что-то пользователю:

| Что | Результат |
|---|---|
| Есть ли неисправность | AUROC 0.79 |
| Где в машине (6 зон) | верная зона в топ-3 ≈ 75 % |
| Какая деталь (12+ семейств) | верная в топ-3 ≈ 45–65 % |
| Знает, что не знает | калиброван, умеет отвечать `uncertain` |

## Два разных числа, и путать их нельзя

Сервер присылает **две** вероятности, и они означают совершенно разное.

`fault_probability` — отдельная голова «есть ли вообще неисправность». В
шипованной модели она откалибрована температурой **3.08**: сырую самоуверенность
специально погасили, заявленная ошибка калибровки ≈ 0.04. Это число можно читать
как обычную вероятность, и оно идёт первой карточкой. Пороги вердикта: ≥ 0.6 —
`fault`, ≤ 0.4 — `normal`, между ними — `uncertain`.

`causes[].p` — **распределение по 21 семейству**, сумма по всем равна единице.
Температура этой головы **1.0**, то есть она не калибрована вовсе. Её 99 %
означают «из версий модель отдала этой почти весь вес», а не «деталь сломана с
вероятностью 99 %». Разница видна на демо-клипе репозитория: выхлоп получает
99 %, при том что сам факт неисправности оценён в 64 %.

Поэтому в подписи карточки стоит «модель ставит сюда», а не «уверенность».
Хвост ранжирования ниже 5 % отбрасывается: модель отдаёт распределение целиком,
и карточка с долей процента читается как найденная неисправность.

## Проверка вне области: почему нужен предохранитель по `segments`

Голова причин раскладывает 100 % по деталям **всегда**, класса «ничего» у неё
нет. Что это значит на практике — замерено, а не предположено:

| Запись | «что-то не так» | Первая версия | `segments` |
|---|---|---|---|
| 5 с тишины | 73 % | выхлоп **100 %** | 0 |
| Чистый синус 440 Гц | 92 % | ШРУС 38 % | 0 |
| Синтетический «мотор» | 47 % | выхлоп 98 % | 0 |
| Демо-клип репозитория | 64 % | выхлоп 99 % | 0 |

То есть на тишине приложение уверенно показало бы «выхлоп 100 %». Ненадёжен при
этом **весь** ответ, а не только детали: «неисправность 92 %» на синусе — тоже
выдумка.

### Предохранителя нужно два

**Первый — `segments`**: сколько чистых механических кусков выделил каскад.
Ноль означает, что разбирали запись целиком, вне области применимости модели.
Тогда экран не показывает ни вердикт, ни версии.

Его, однако, **не хватает**, и вот почему. Порог громкости в каскаде
относительный: `rms > max(0.005, percentile(rms, 20) * 1.5)`. Ровный звук его
не проходит, а перепад — проходит. Запись «я молчу», но с парой шорохов от руки
даёт два «механических» куска. И тогда:

| Запись | сегментов | вердикт | первая версия |
|---|---|---|---|
| Тишина + шорохи | 2 | **normal, 32 %** | выхлоп **86 %** |

Голова «есть ли поломка» ответила правильно — «ничего нет». А список деталей
всё равно уверенно назвал выхлоп.

**Второй предохранитель — вердикт.** Версии показываются только при
`verdict == "fault"`. Голова причин не умеет отвечать «ничего», а голова
`kind` умеет и вдобавок откалибрована — она и служит воротами.

**Что осталось непроверенным:** ноль сегментов дают все четыре записи выше,
включая демо-клип самого репозитория. Даёт ли настоящая запись работающего
мотора с телефона сегменты > 0 — проверить без настоящей машины нельзя. Если
окажется, что не даёт, предохранитель придётся смягчить: смотреть не на число
сегментов, а на их суммарную длительность или на порог из `clean()`.

Классы `cause` в шипованной модели (21) не совпадают со списком семейств в
`pipeline/build.py`. В ней есть `transmission`, `cooling_other`, `mounts`,
`other` и — отдельным классом — `bad_wheal_bearing` рядом с `wheel_bearing`
(опечатка в их разметке). Словарь покрывает и их.

## Как поднять сервер

На устройстве это не запустить: CLAP весит около 2 ГБ и требует torch.
Приложение ходит к серверу.

```bash
cd ~/Desktop/car-diagnosis
uv venv --python 3.11 && source .venv/bin/activate
uv pip install -e ".[web]"

cardiag serve --model models --host 0.0.0.0 --port 8077
```

- `--model models` — предобученная модель, которая лежит в репозитории. Без
  неё сервер поднимется, но вернёт `model_loaded: false`, и экран об этом
  скажет.
- `--host 0.0.0.0` — обязательно. По умолчанию сервер слушает 127.0.0.1, и
  телефон до него не достучится. Обратная сторона: сервер виден всей локальной
  сети и авторизации у него нет. Для отладки дома это нормально, дальше — нет.
- Первый разбор скачивает CLAP (~2 ГБ) и потому долгий; дальше веса кэшируются.
- `ffmpeg` не нужен, пока приложение шлёт WAV: его читает `soundfile`. `cardiag
  doctor` всё равно пометит ffmpeg как блокирующий — это про скачивание роликов,
  не про разбор.

Проверка живости: `curl http://127.0.0.1:8077/health` → `{"status":"ok",
"model_loaded":true}`.

## Где что в приложении

| Файл | Что делает |
|---|---|
| `AppMVP/Core/Services/CarDiagnosis.swift` | адрес сервера, разбор ответа, русский словарь зон и семейств |
| `AppMVP/Core/Services/AudioLevelMeter.swift` | пишет WAV тем же тапом, которым считает громкость |
| `AppMVP/Features/Issues/IssuesScreen.swift` | отправка, состояние ожидания, раскладка ответа по карточкам |
| `AppMVP/Resources/Info.plist` | разрешение ATS на локальную сеть |

Адрес сервера — константа `DiagnosisEndpoint.baseURL`. Сейчас в ней Mac
разработчика; на другой сети адрес сменится. Пустая строка возвращает раздел
на заглушку `IssuesStub`.

## Формат обмена

`POST /diagnose`, `multipart/form-data`, поле `file`. Ответ:

```json
{
  "verdict": "fault",
  "fault_probability": 0.638,
  "regions": [{"zone": "suspension/steering", "p": 0.832}],
  "causes": [{"part": "exhaust", "p": 0.991, "note": ""}],
  "engine_knock_probability": 0.057,
  "note": "...treat as triage, not a final diagnosis.",
  "model_loaded": true
}
```

Заголовок `Origin` клиент не ставит намеренно: сервер отбивает по нему
межсайтовые запросы, а у родного клиента его быть и не должно.

Словарь зон и семейств взят из `pipeline/build.py` целиком — шесть зон и 22
семейства. Незнакомый ключ доедет до экрана английским идентификатором, поэтому
при обновлении `cardiag` словарь стоит сверять.
