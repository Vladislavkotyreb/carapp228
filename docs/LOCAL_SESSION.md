# Локальная сессия на маке: сборка, симулятор, тесты

Как дать агенту руки до Xcode. Проверено по документации Claude Code
2026-09-22; ссылки в конце.

## Коротко

**Расширения для Xcode не существует.** Есть VS Code и JetBrains, Xcode
в этом списке нет и не было.

Зато у **десктопного приложения Claude Code есть панель симулятора iOS**:
агент собирает, ставит, запускает приложение, сам тапает по экрану и читает
его, чтобы проверить свою же правку. Это ровно то, чего не хватало: до сих
пор жесты проверял человек.

**Из облачной сессии (claude.ai/code, где идёт эта работа) симулятор
недоступен.** Документация говорит прямо: панель работает только в локальных
сессиях; в облачных и SSH агент живёт на машине, которая до симуляторов мака
не дотянется. Так что «подключить» облачную сессию к Xcode нельзя — можно
только перенести работу на мак.

## Что поставить

1. Скачать десктопное приложение Claude Code для macOS:
   https://claude.ai/api/desktop/darwin/universal/dmg/latest/redirect
   Node.js и CLI отдельно не нужны, приложение несёт Claude Code внутри.
2. Версия приложения — **v1.24012.0 или новее** (Claude → Check for Updates).
3. Xcode **26.x**. Панель пока **не работает с Xcode 27**: там вместо
   Simulator появился Device Hub. У нас 26.6 — подходит. Проверить:
   `xcode-select -p`; переключить, если надо:
   `sudo xcode-select -s /Applications/Xcode-26.4.app`.
4. Вкладка **Code** → окружение **Local** → **Select folder** → папка проекта.

Панель в публичной бете, доступна на Pro, Max, Team и Enterprise (кроме
Enterprise с включённой конфигурацией HIPAA).

## Как это выглядит в работе

Отдельной команды нет. Панель открывается сама, когда агент запускает
приложение в симуляторе. Формулировать задачу надо через запуск:

```
Собери приложение и запусти в симуляторе, проверь онбординг
Запусти на симуляторе iPhone SE
```

Первый раз на каждое устройство приложение спросит разрешение. После этого
тапы, ввод, запуск и скриншоты идут без вопросов. Отдельно спрашивается
только два действия: открыть URL на устройстве и **собрать приложение**
(`xcodebuild` выполняет скрипты сборки на маке) — они подчиняются режиму
разрешений сессии.

Что можно делать руками в той же панели: тапать и свайпать мышью, `Cmd+Shift+H`
домой, `Cmd+L` блокировка, `Cmd+←/→` поворот, `Cmd+S` скриншот, `Cmd+R`
запись экрана (файлы падают на рабочий стол). Пока агент ведёт устройство,
над экраном висит значок «Claude is using this device» — в это время лучше
не тапать, иначе результат будет о вашем касании, а не о приложении.

Устройство привязано к сессии: параллельные сессии не делят симулятор.
Приложение гасит те симуляторы, которые само загрузило, через десять минут
после отсоединения или при выходе. Те, что загрузили вы, не гасит.

**Скриншоты устройства уходят в Anthropic** и хранятся по обычным правилам
хранения переписки. На симулятор, с которым работает агент, не входить в
настоящие аккаунты.

**Физический iPhone агент не водит** — только симуляторы. Проверка на
устройстве остаётся ручной, см. [DEVICE_TESTING.md](DEVICE_TESTING.md).

## Из CLI

Если привычнее терминал, `claude` в папке проекта тоже работает, но панели
симулятора там нет: из CLI агент дотягивается до симулятора через computer
use, то есть водит мышью по вашему экрану. Это медленнее и хрупче, и требует
разрешений в «Универсальном доступе». Для этого проекта десктопное приложение
удобнее.

## Чтобы не подтверждать каждую команду

В локальной сессии агент будет спрашивать разрешение на каждый `xcodebuild`
и `xcrun`. Если надоест — положить в `.claude/settings.local.json` (он в
`.gitignore`, у каждого свой):

```json
{
  "permissions": {
    "allow": [
      "Bash(xcodebuild:*)",
      "Bash(xcrun simctl:*)",
      "Bash(xcrun devicectl:*)",
      "Bash(./tools/run-pure-checks.sh)",
      "Bash(python3 tools/check-typography.py)",
      "Bash(python3 tools/check-project.py)",
      "Bash(python3 tools/check-catalog.py)"
    ]
  }
}
```

Это ваше решение, а не моё: список снимает подтверждения на сборку, а сборка
выполняет скрипты проекта. Файл не в git намеренно — режим доверия у каждого
свой.

Заслонка журнала (`.claude/hooks/require-journal.sh`) работает в любой
сессии и от этого списка не зависит.
