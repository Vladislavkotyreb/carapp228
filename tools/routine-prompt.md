Процедура целиком — в навыке `.claude/skills/inbox/SKILL.md`. Прочитай его и следуй ему; ниже только то, что важно не перепутать.

1. `git fetch origin && git checkout main && git pull` — свежее состояние. Потом `python3 tools/inbox-extract.py` (строки `- [ ]` из заметок становятся задачами и багами) и `python3 tools/inbox-scan.py` (очередь на неделю, дубли уже сняты). Очередь пуста — заканчивай молча: ни ветки, ни коммита, ни отчёта, ни уведомления.

2. Ветка `claude/inbox-$(date +%F)` от `origin/main`. В `main` не пушить, PR не открывать.

3. Две зоны, и они не смешиваются.
   **`fix` — баги (`inbox/bugs/`).** Чинить кодом, включая вью. `scope` пуст — сперва найти, где баг живёт. Не воспроизводится по коду — `blocked` и строка, чего не хватает; чинить по неверному описанию нельзя.
   **`brief` — задачи (`inbox/tasks/`).** Код НЕ трогать. В заметку — раздел «## Пути реализации»: два-три пути, по одной-две строки на каждый (что делаем, где в проекте, цена, чем плох), последней строкой — какой разумнее. Не длиннее десяти строк: человек читает с телефона. `status: needs-review`, заметка остаётся в `tasks/`.
   **`review`** — баг вне кода проекта или в `Canary.xcodeproj`: только разбор в заметку, `needs-review`.

4. Xcode, симулятора и рендеров Figma здесь нет. Это причина честно пометить правку непроверенной, а не причина её не писать: рядом с каждой правкой — «сборкой и сверкой с макетом не проверено», и в заметке, и в отчёте. **Не заявлять собранным то, что не собиралось.** Перед правкой вью прочитать `docs/TRAPS.md`. 7. Отчёт — `inbox/reports/<дата>.md`, коротко: починено / застряло / задачи с путями реализации (по строке на задачу и вики-ссылка на заметку), с именем ветки. Он возвращается в Obsidian и читается с телефона.

8. Сообщить инструментом `PushNotification` одной строкой: сколько багов починено, сколько задач разобрано, имя ветки.
