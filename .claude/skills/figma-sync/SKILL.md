# Интерфейс из кода — сразу в Figma

Договорённость с пользователем (2026-09-26): сделали что-то интерфейсное в
коде — в том же заходе кладём это в Figma. Дизайнер работает в Figma и не
должен узнавать о новом экране из симулятора.

Файл: `9GXgWezTGI6TjklsnuBns2` (Beepy). Правила проекта —
[CLAUDE.md](../../../CLAUDE.md), они сильнее этого файла.

## Когда

- Изменилось то, что видно: новый экран, шторка, состояние, кнопка, цвет,
  начертание, текст на экране, отступ. Чисто логические правки, `Core/Pure`,
  тесты, доки — не нужно.
- Правка по замечанию к существующему макету — обновить кадры на странице
  фичи, а не заводить новую.

## Что класть

Одна страница на фичу, имя `N Тема` по порядку существующих
(«6 Прослушивание и запись в сервис»), вставить после последней страницы
дизайна, не в конец за «Sandbox». Одна рамка-обёртка во всю страницу:

1. **Описание слева** (колонка 520): заголовок, зачем фича, «Как это
   работает» по шагам, правила и пороги (со значениями из кода), «Правки
   ДД.ММ» списком — что именно поменялось, со ссылкой на токен
   (`Fills/Tertiary`, Regular 13). Внизу — файлы кода и откуда кадры.
2. **Макеты справа** в ряд, по порядку флоу, подпись над каждым
   «1. Экран: что на нём важно». У подписи **фиксированная высота** (42) —
   иначе одна двухстрочная подпись сдвигает свой кадр вниз.
3. **Ниже отдельной рамкой — «Сверка: кадры симулятора»**: те же состояния
   скриншотами, для попиксельного сравнения.

**Макеты перерисовываются слоями, а не вставляются скриншотами** — прямое
требование пользователя (2026-09-26, капсом: «ИМЕННО ПЕРЕРИСУЙ»). Скриншот в
рамке макетом не считается: его не поправить, из него не взять размер и
цвет. Экран 402×874 (размер файла), тёмная тема, токены приложения из
`Core/Design/Theme.swift`, те же тексты, что в коде. Из файла брать готовое:
`Status Bar` (клон `46225:7467`, тексты и значки перекрасить в белый).
Тулбар шторки рисовать самому: клон набора приходит с «Title», пустым
значком и синей галочкой — не как в приложении.

Значки — текстом SF Pro с кодом SF Symbol, не картинкой. Коды из шрифта не
читаются по имени (глифы названы `uniXXXXXX`), их находит
`tools/sf-symbol-codepoint.swift` сравнением формы (см. шапку файла).
Уже найденные: car.fill 100659, xmark 100184, checkmark 100185,
drop.fill 100812, line.3.horizontal.decrease 100713, arrow.up.right 10012F,
thermometer.medium 1013C3, circle.circle 100A01, square.dashed 100FEB,
wrench.and.screwdriver.fill 10090B, bolt.fill 1002E6, fan.fill 10104C,
point.topleft.down.to.point.bottomright.curvepath 1008F1.

## Порядок

1. Собрать и поставить на симулятор (команда из CLAUDE.md), при пустой базе —
   посеять машину. Пройти флоу, снимая кадры
   `xcrun simctl io <UDID> screenshot fN.png` в scratchpad. Снимать через
   2–4 с после действия: анимации (переключатель, шторка) на 2 с ещё идут и
   дают ложный кадр. `simctl` при этом может отдать **старый** кадр — сомнение
   проверять `screenshot` инструмента симулятора. Переключатель (`UISwitch`)
   мгновенный синтетический тап не переключает — нужен `duration: 0.2`;
   кнопки SwiftUI переключаются и так.
   Нужны находки с деталями, а микрофон симулятора слышит тишину — запуск с
   `SIMCTL_CHILD_BEEPY_STUB_DIAGNOSIS=1 xcrun simctl launch …` (только DEBUG).
2. Посмотреть все кадры одной полосой (PIL, 234×506 каждый) до загрузки:
   верное ли состояние на каждом.
3. Загрузить скилл `figma-use` (`get_figma_skill`), потом `use_figma`:
   собрать экраны слоями одним скриптом-построителем (функция на экран,
   параметры — состояние), автолейаут для всего, что стоит стопкой. Шрифт —
   `SF Pro`: Regular / Medium / Semibold / Bold и Condensed-начертания есть.
   Картинки (кадры каталога и т. п.) — один раз `upload_assets` без
   `nodeIds`, дальше заливка по `imageHash`.
4. Скриншоты для «Сверки» — `upload_assets` с `nodeIds` = id рамок, POST
   `curl -F "file=@fN.png;type=image/png"` **по одному и сверить
   `placedOnNodeId`**. Дважды 2026-09-26 при `count > 1` первый URL отвечал
   404, а каждый следующий ложился на рамку раньше своей. Лечится так:
   переставить заливки скриптом на одну рамку вправо и догрузить первый
   кадр отдельным вызовом с `count: 1` — одиночный URL кладёт верно.
5. `get_screenshot` обёртки (maxDimension 2400) и сравнить со скриншотами
   симулятора рядом: схлопнутые по ширине строки (у `HUG`-строки с текстом
   ставить `FIXED` и `layoutGrow`), неверные значки, край прокрутки поверх
   контента, обрезанный текст. Один проход правки,
   один повторный кадр.
6. Дать пользователю ссылку на страницу
   `https://www.figma.com/design/9GXgWezTGI6TjklsnuBns2/?node-id=<id обёртки>`
   и записать в журнал страницу и id обёртки.

## Никогда

- Не трогать чужие страницы и кадры дизайнера — только свою страницу фичи.
- Не выдавать непроверенный кадр за состояние экрана: снят не тот момент —
  переснять.
- `figma.currentPage = …` не работает — только `setCurrentPageAsync`,
  один раз за вызов.
- `query()` не понимает кириллицу в селекторе — ходить по `children`.
