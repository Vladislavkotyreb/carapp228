# inbox — вход для задач и багов из Obsidian

Сюда Obsidian кладёт заметки, отсюда их каждое утро разбирает автоматика
(навык `/inbox`, Routine «Canary — утренний разбор inbox»). Отчёт возвращается
в `reports/` тем же git-ом и виден в Obsidian, плюс приходит пушем в приложение
Claude.

## Папки

| Папка | Что лежит |
|---|---|
| `tasks/` | задачи: что сделать |
| `bugs/` | баги: что сломано |
| `done/` | разобранное — сюда файл переезжает сам |
| `reports/` | отчёт за день, `ГГГГ-ММ-ДД.md` |
| `_templates/` | шаблоны для Obsidian Templater |
| `attachments/` | скриншоты из заметок |
| `*.md` в корне | твои заметки из хранилища (`Таски.md` и что ещё напишешь); строки `- [ ]` в них становятся задачами |
| `Мои задачи.md` | личный список — помечен `canary: ignore`, разбор его не читает |
| `Личное/` (только в хранилище) | остаётся на маке: в репозиторий не копируется вовсе |

## Два способа поставить задачу

**Обычной заметкой.** Пишешь с телефона как пишешь — списком с галочками.
`tools/inbox-extract.py` берёт каждую строку `- [ ]` и заводит под неё задачу
в `tasks/`, один раз на строку (помнит в `.extracted.json`). `scope` у такой
задачи пуст, поэтому разбор код не тронет: выяснит, где это делается, напишет
план и оставит решение тебе. Этого хватает в большинстве случаев.

**Никак** — если заметка не для разбора. Шапка из трёх строк в начале файла:

```markdown
---
canary: ignore
---
```

и галочки из неё задачами не станут. Так сделан `Мои задачи.md`; пометить
можно любую заметку, и переименование её не расколдует. Пустая `- [ ]` —
заготовка, а не задача, её извлечение пропускает и без пометки.

**Совсем мимо репозитория** — папка `Личное` в хранилище. Синхронизация её
не копирует, поэтому в git она не попадает ни при каком раскладе, а репозиторий
публичный. Туда — недодуманное, адреса стендов, что угодно. Папка заводится
сама при первом прогоне синхронизации, вместе с `Черновик.md`.

Разница с `canary: ignore` простая: помеченная заметка в репозитории лежит,
просто не разбирается; папка `Личное` до репозитория не доезжает вовсе.

**Отдельной заметкой по шаблону** — когда хочется, чтобы код правился сам.
Тогда нужен `scope`: путь внутри `AppMVP/Core/Pure/`, `docs/`, `tools/`
или `inbox/`. Формат ниже.

## Формат заметки

Фронтматтер обязателен: по нему автоматика решает, брать файл или нет.
Заметка без `status` не берётся вовсе — это защита от черновика, случайно
попавшего в папку.

```markdown
---
status: todo
kind: bug
scope: AppMVP/Core/Pure/ServiceMath.swift
---

Остаток до ТО считается от одометра, а не от пробега на момент последнего ТО:
после замены масла на 150 000 «ТО через» показывает 10 000 вместо 15 000.

## Как воспроизвести
1. Завести машину с пробегом 150 000.
2. Отметить замену масла.
3. Главный экран: «ТО через 10 000 км».
```

### Поля

- **`status`** — `todo` (взять в работу), `doing`, `done`, `blocked`,
  `needs-review` (правка сделана, но проверить может только человек).
  Автоматика берёт **только `todo`**.
- **`kind`** — `bug` или `task`. Влияет на то, просит ли автоматика шаги
  воспроизведения.
- **`scope`** *(необязательно)* — путь к файлу или папке. Сужает поиск и
  экономит время прогона.
- **`priority`** *(необязательно)* — `high` берётся первым.

## Что автоматика чинит сама

Только то, что можно проверить без Xcode и без симулятора:

- логика в `AppMVP/Core/Pure/` — её накрывает `./tools/run-pure-checks.sh`;
- русская типографика в строках — `tools/check-typography.py`;
- документы в `docs/`;
- скрипты в `tools/`.

Всё остальное — вьюхи, жесты, `project.pbxproj`, вёрстка под макет — автоматика
**не правит**, а пишет диагноз и план в саму заметку и ставит `needs-review`.
Причина в [CLAUDE.md](../CLAUDE.md): в облаке нет ни Xcode, ни симулятора, ни
попиксельной сверки с Figma, а «починка» вью без сверки — это регрессия,
о которой узнаёшь на устройстве.

## Куда уходят правки

Ветка `claude/inbox-ГГГГ-ММ-ДД`, один коммит на заметку. `main` не трогается,
PR автоматика не открывает — сливаешь сам, посмотрев диф.

## Как это связать с Obsidian

**Заметки на GitHub относит мак, а не телефон.** Пишешь с телефона в папке
`canary` своего хранилища, Obsidian синхронизирует её на мак, а там раз в день
`tools/inbox-sync.sh` переносит заметки в `inbox/` и пушит. Утренний разбор
в облаке видит только GitHub — телефон ему недоступен.

Установка на маке, один раз:

```bash
# заполнить REPO и VAULT в начале скрипта
chmod +x tools/inbox-sync.sh
tools/inbox-sync.sh                     # разовый прогон: проверить, что пути верны
cp tools/dev.canary.inbox-sync.plist ~/Library/LaunchAgents/
launchctl load ~/Library/LaunchAgents/dev.canary.inbox-sync.plist
```

Скрипт ходит в обе стороны: заметки из хранилища едут в репозиторий, а оттуда
зеркалом возвращаются `done/` и `reports/` — разобранная заметка исчезает
из `tasks/` на телефоне, и завтрашний разбор не берёт её снова. Запуск —
в 08:45 и при входе в систему, за четверть часа до разбора. Мак спал — launchd
догоняет после пробуждения. Журнал: `/tmp/canary-inbox-sync.log`.

**Скриншоты.** В Obsidian: Настройки → «Файлы и ссылки» → папка для вложений →
`attachments` внутри `canary`. Тогда картинка из заметки доедет вместе с ней,
и разбор её откроет.

**Почему не плагин Git прямо на телефоне.** Репозиторий весит 85 МБ истории
и 71 МБ картинок в `AppMVP/`. Плагин на мобиле — это git, переписанный на JS;
такой клон он либо не вытянет, либо будет тянуть при каждом старте. На маке
это обычный `git` и обычный `rsync`.

**Симлинком тоже не получится.** Если хранилище лежит отдельно и внутри него
симлинк на `inbox/`, git хранит симлинк ссылкой и внутрь не заходит — заметки
не попадают ни в один коммит, а выясняется это утром на пустой очереди при
полной папке.

Проверить, что связь работает: написать заметку с телефона, дождаться
синхронизации Obsidian, запустить `tools/inbox-sync.sh` руками и посмотреть
`python3 tools/inbox-scan.py` — заметка должна оказаться в очереди.
