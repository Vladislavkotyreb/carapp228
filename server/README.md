# Сервер Beepy

Синхронизация поездок из приложения и API админки — один процесс на Node
(Hono). База — Postgres, по 152-ФЗ только на площадке в РФ
([`docs/DATABASES.md`](../docs/DATABASES.md)). Почему так устроено —
[`docs/BACKEND.md`](../docs/BACKEND.md), раздел «Синхронизация поездок».

## Что уходит на сервер

Только с согласия человека (экран в «Ещё»). Аккаунт анонимный: ни имени, ни
телефона, ни почты. У машины — название и пробег, у поездки — время, метры и
машина. Госномер, VIN, маршруты и адреса остаются на телефоне.

## Запуск

```bash
npm install
cp .env.example .env.local   # логин и хеш пароля админки
npm run hash-password        # хеш для ADMIN_PASSWORD_HASH
npm run dev                  # http://127.0.0.1:8787, база — PGlite в ./data
```

Без `DATABASE_URL` база — PGlite: тот же Postgres, собранный в WebAssembly,
без установки. Только для разработки: `NODE_ENV=production` без
`DATABASE_URL` не стартует.

Админка — сборка из `crm/` (`npm run admin:build` там), сервер отдаёт её по
`/admin`. В разработке интерфейса удобнее `npm run admin:dev` в `crm/`: запросы
к `/admin/api` он сам проксирует сюда.

Демо-данные для локального сервера: `npm run seed`.

## Проверка

```bash
npm test          # 26 проверок на PGlite в памяти
npm run typecheck
TEST_DATABASE_URL=postgres://…/beepy_test npm test   # то же на настоящем Postgres
```

База для `TEST_DATABASE_URL` должна называться `*_test`: тесты стирают её схему.

## Docker

```bash
docker compose up --build    # сервер + Postgres 17, пароли — из .env
```

Наружу смотрит только `127.0.0.1:8787`; на площадке перед сервером ставится
nginx с TLS, и с ним включается `ADMIN_SECURE_COOKIES=1`.

## API

| Метод | Путь | Что делает |
|---|---|---|
| `POST` | `/v1/accounts` | новый аккаунт и устройство; без действующего согласия — 409 |
| `POST` | `/v1/sync` | изменения телефона → изменения с других устройств (курсор, страницы по 500) |
| `DELETE` | `/v1/account` | удалить аккаунт со всеми данными |
| `GET` | `/v1/health` | жив ли сервер и база |
| `POST` | `/v1/installs` | токен установки для поиска (без согласия и персональных данных) |
| `POST` | `/v1/vehicles/lookup` | машина по госномеру через поставщика; 404 — нет, 429 — лимит |
| `POST` | `/v1/vehicles/price` | рыночная оценка по VIN |
| `POST` | `/admin/api/login`, `/logout` | вход в админку, cookie HttpOnly |
| `GET` | `/admin/api/stats`, `/accounts`, `/accounts/:id`, `/audit` | сводка, аккаунты, журнал |
| `DELETE` | `/admin/api/accounts/:id` | удалить аккаунт |
| `POST` | `/admin/api/devices/:id/revoke` | отозвать устройство |

Каждый просмотр и каждая правка в админке пишутся в `audit_log`.

## Прокси поиска: подготовка к размещению (14.11.2026)

Прокси ещё не опубликован. Release 11 не содержит адреса сервера; поиск
в нём скрыт. Подключение публичного HTTPS-адреса потребует новой сборки.

- `AVTOVINCOD_TOKEN` задаётся только в окружении сервера; Docker Compose
  передаёт его контейнеру. Не записывать секрет в образ, git или Info.plist.
- `LOOKUP_PER_INSTALL_DAILY` ограничивает все попытки установки за скользящие
  24 часа. `LOOKUP_DAILY_FOUND` — общий резерв за 24 часа: найденные,
  выполняющиеся и запросы с неизвестным исходом. Подтверждённое «не найдено»
  освобождает общий резерв, но остаётся попыткой установки.
- Резерв создаётся атомарно в БД до вызова поставщика. Сетевой таймаут или
  падение процесса не возвращает потенциально потраченный запрос в бюджет.
  Ноль в любом лимите отключает вызовы, неверное число останавливает запуск.
- Это ограничения API на установку и на весь сервис. Они **не являются**
  проверкой двух машин на Apple-аккаунт: токен установки не подтверждает
  Apple ID, а число сохранённых машин сейчас проверяется приложением.
- Ответы поиска имеют `Cache-Control: no-store`. Номер/VIN не записываются
  в `lookup_log`. Обратный прокси также не должен писать тела и заголовки
  авторизации; X-Forwarded-For нужно заменять реальным IP клиента.
- У AvtoVinCod поиск занимает до 45 секунд; сервер ждёт 60, iOS — 75.
  Обратному прокси нужен таймаут не меньше 75 секунд.
  Документация: https://avtovincod.ru/docs/gos2vin/

До включения для пользователей: проверить SSH/ресурсы VPS, HTTPS, резервные
копии БД, отдельный токен поставщика и согласованный бюджет. Для первого
развёртывания держать `LOOKUP_DAILY_FOUND=0` до проверки конфигурации.
Не открывать наружу синхронизацию, админку и оценку цены ради одного поиска.
Проверить запрос на бесплатном тестовом номере поставщика, затем реальный
поиск в пределах согласованного бюджета.

Выбран Netcup VPS (Нюрнберг). Это отличается от прежнего плана БД в РФ:
до включения реальных запросов нужно согласовать обработку и размещение
данных и обновить политику/декларацию App Privacy/Notes. Текущая опубликованная
политика описывает Release 11 без серверного поиска. Не переносить на этот
VPS аккаунты и поездки только потому, что их код есть в общем сервере.
